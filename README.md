# Backend for BaaS

This is the API for BaaS (working title). It is written in GoLang, using sqlc and
chi as the main dependencies.

## Architecture

Three layers, wired bottom-up in `cmd/api/main.go`:

```
Handler (internal/handlers) → Service (internal/services) → Repository (internal/repositories)
```

Interfaces are defined in the `services` package; the repository maps the database
rows (generated by sqlc into `internal/repositories/db`) to the domain models in
`internal/models`. See the `three-layer-architecture` skill for the full convention.

The HTTP surface is documented in [`openapi.yml`](./openapi.yml).

## Running locally

The backend listens on `:8080` and needs a Postgres database.

### 1. Start the database

```sh
docker compose up -d db
```

The database credentials come from a `.env` file (git-ignored) next to
`compose.yml`. It also feeds `DATABASE_URL` below. See `.env.example` for the
expected keys.

### 2. Run the backend

The server is configured entirely through environment variables. For **local HTTP
development with the frontend dev server** (Vite on `http://localhost:5173`), the
important ones are:

| Variable           | Local dev value                                              | Default | Notes |
| ------------------ | ------------------------------------------------------------ | ------- | ----- |
| `DATABASE_URL`     | `postgres://baas_user:...@localhost:5432/baas?sslmode=disable` | –       | Required. |
| `JWT_SECRET`       | any string ≥ 32 chars                                        | –       | Required. |
| `CORS_ENABLED`     | `true`                                                       | `false` | Lets the browser send credentialed cross-origin requests. |
| `FRONTEND_URL`     | `http://localhost:5173`                                      | –       | Required when `CORS_ENABLED=true`; the single allowed origin. |
| `COOKIE_SECURE`    | `false`                                                      | `true`  | Auth cookies over plain HTTP; **leave at the `true` default in production.** |
| `SAME_SITE_STRICT` | `false`                                                      | `true`  | `Strict` blocks the cookie on the cross-site XHR from `:5173`; `Lax` lets it through. |
| `DB_AUTO_MIGRATE`  | `false`                                                      | `false` | Migrations otherwise run on start via dbmate. |

Do **not** commit real secrets. Keep them in `.env` (git-ignored) or your shell.

Example:

```sh
CORS_ENABLED=true \
FRONTEND_URL=http://localhost:5173 \
COOKIE_SECURE=false \
SAME_SITE_STRICT=false \
DATABASE_URL="postgres://baas_user:supersecret@localhost:5432/baas?sslmode=disable" \
JWT_SECRET="dev-secret-dev-secret-dev-secret-32" \
go run ./cmd/api
```

## Auth endpoints

- `POST /api/auth/register` — register a **farmer** or **customer**; sets the auth
  cookies and returns `{id, role}`. Admins are seeded in the database, not
  registered here.
- `POST /api/auth/login` — sets the auth cookies and returns `{id, role}`.
- `GET /api/auth/me` — returns `{id, role}` for the authenticated cookie.

Login/register set two HttpOnly cookies: `access_token` (`Path=/`, 15 min) and
`refresh_token` (`Path=/api/auth/refresh`, 7 days). A `/api/auth/refresh` endpoint
is not implemented yet.
